# Working instructions

- Keep repository content in English. Conversation with the owner may be Russian.
- Keep mod UI copy in `localization/ui/<game-language>.json`; `eng.json` is the canonical fallback and translation values use their target language. Preserve matching keys/format arguments. Player language selection and locale subscriptions belong to RitsuLib I18N, disposed with the player UI. Native game names/descriptions stay game-owned; Core/Extension must remain game-independent. Catalog edits require rebuild/reload because distribution embeds the same source JSON files.
- Native game facilities are the first choice: use real intent widgets, hover-tip scenes, approved native arrow assets, game fonts/palette and native interactions before custom UI. Library adapters come next; custom code needs a demonstrated native/library gap recorded in existing research. Matching colors/textures alone does not make a custom widget native.
- Use Kreon Bold for authored mod labels and promotional titles/covers. In-game reuse res://themes/kreon_bold_glyph_space_two.tres and native fallback handling; keep game-owned widget typography. For external graphics, use the actual Kreon font for exact typesetting, not ornate metallic/cinematic substitutes. The approved cover uses flat cream lettering with a restrained dark outline; generated lettering is an approximation, not actual font embedding.
- Use this repository's README and local instructions for standalone development. Linked maintainers may also follow the private workspace baseline; public contributors must not need access to it. Original mod code is MIT-licensed with Xaaalera attribution; preserve third-party licenses and game ownership.
- Search retained accessible evidence and primary sources before changing an approach. Linked maintainers record evidence/failures in the private workspace journal; public contributors include reproducible findings in their issue or PR.
- This mod displays probability distributions and state graphs, never seeded future selections. Do not read, clone, advance or replace RNG or execute game transition/weight/condition callbacks during inspection.
- Model source-verified gameplay phases and their transition triggers before drawing cycles. Show mutually exclusive phases as separate native sections, include event-driven intent replacements, and keep unknown semantics explicit. A source-verified action that removes the monster ends its reference even when raw FollowUpState repeats; never invent a death-trigger transition from graph connectivity alone. Keep raw data intact. Never interpret the reference as a seeded next-action prediction.
- Anchor horizontal hover references above their enemy and preserve a valid open position. Use actual visible relic-holder rectangles as obstacles. Compact spacing and phase content before relocating; do not stack phases into a tall panel covering the enemy. Omit redundant enemy-name/move-cycle headers and generic damage disclaimers. Verify diagnostic target identity across encounter changes instead of assuming overlay/native list order agrees.
- Wrapped deterministic action chains read in alternating row directions. Use a nearby downward continuation between rows and a separate outer return corridor; continuation and return must not share a positive-length segment. Native containers still position cells; preserve logical action order independently of visual child order.
- Place compact forecasts above the native current-intent container, using parent-coordinate transforms rather than fixed hitbox offsets. Compare actual global rectangles when validating scaled creatures. Forced shared-entry markers must tolerate unlogged native replacements; use public predecessor history and preserve uncertainty. Terminal presentation metadata must not alter the raw probability engine or truncate unresolved paths.
- Keep probability logic independent of game APIs and SDK internals. Share behavior between native player and SDK adapters.
- Own game UI, timer and subscriptions in the resident adapter; collectible logic exchanges BCL/JSON data only. Preserve unloadability after real invocation.
- Use pinned compatible BaseLib/RitsuLib dependencies and native game loading. Finished player packages have no SDK dependency.
- Keep English Workshop title/description, explicit dependency item IDs, tags and intended visibility in workshop.json. Show the owner the Russian translation before publishing new listing copy. Follow the local README publishing procedure; retain mod_id.txt after creation and inspect remote state before retrying an ambiguous upload failure. Credit developer Xaaalera and distinguish the actual Steam publishing profile if its displayed name differs. Local preparation is not Workshop delivery acceptance.
- Keep exactly one owned test game; the owner's separate Steam game may coexist and must never be controlled or lose focus/input to our work. Revalidate owned PID/path/UTC creation/session before control.
- Every mod release must include genuine owned-game demonstration screenshots with English game/mod UI, captions and promotional text. The owner gives standing authorization for these release captures. Set the actual owned game to English and recapture; never translate or generatively redraw screenshots. Preserve originals privately, inspect useful/readable native UI, upload the complete intended gallery and verify it remotely. Cover art alone is insufficient. Other screenshots require an explicit request; diagnostics/background commands alone do not prove physical/rendering acceptance.
- Local game binaries, decompiled content, profiles, saves, raw logs and evidence stay in ignored .local directories.
- Install the pinned executable review gates before substantive implementation. Use actual configured independent reviewers and never bypass a gate or invent results.
